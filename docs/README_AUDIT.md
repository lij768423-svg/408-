# README 三线审计

审计目标：确保主 README 对第一次访问仓库的人足够清楚、与当前代码一致，并避免同一内容在多个位置重复维护。

## 1. 新用户能否看懂

### 新用户检查项

- 开头是否能在一分钟内说明项目用途。
- 是否明确区分纯静态模式和完整后端模式。
- 是否提供可以直接复制执行的启动命令。
- 是否说明不能直接双击 `index.html` 的原因。
- 是否给出从打开页面到完成第一轮刷题的操作路径。
- 专业部署和接口细节是否不会阻塞普通用户阅读。

### 新用户审计结果

- README 开头增加“只想本地刷题 / 需要完整能力”两条入口。
- 快速启动缩短为 Python 和 Node.js 两种 HTTP 服务方式。
- 增加能力对照表，明确 `LOCAL` 模式不需要登录。
- 新用户路径改为打开页面、选择范围、作答、复盘和导出记录。
- 新用户路径补充学习仪表盘、今日优先章节和“今日复习”的使用顺序。
- 部署和后端接口移到独立文档，主 README 保持为面向仓库访问者的精简入口；完整桌面端操作细节集中到 `USAGE.md`，页面内“使用说明”保留就地提示。

## 2. 文档是否与代码一致

### 一致性检查项

- 题量、运行模式、路由和刷题模式是否与代码一致。
- README 提到的按钮、配置入口和快捷键是否真实存在。
- `/api/*` 方法、请求体和响应格式是否与前端调用一致。
- 测试命令是否能在当前仓库直接通过。
- 项目结构是否包含当前关键文件。

### 一致性审计结果

- 题量改为 `2386` 条记录、`2378` 道当前可见题目。
- 删除不存在的浏览器侧 AI Base URL、模型和 Key 配置说明。
- 删除未实现的 A-D 和 F 全局快捷键；补充当前真实存在的搜索与章节方向键、原生按钮 Enter/Space、`Ctrl/Cmd + K` 与 `Esc`。
- 明确 AI 只调用同源 `/api/ai/status` 和 `/api/ai/chat`。
- 补充认证、进度、AI 流式输出和知识库请求体契约。
- 项目结构补充 `check-static.js`、登录介绍页和拆分后的文档。
- 路由、模式和进度字段补充 `#/dashboard`、今日复习、`reviews` 与 `dailyActivity`。
- `npm test` 已通过语法、数据、间隔复习算法和 Playwright 静态烟测；`npm run test:e2e` 已覆盖静态模式与模拟完整后端的关键流程。
- 已移除下线的“批量串讲”和“关联题目”说明，AI 文档只描述当前保留的单题追问、上下文复制与显式保存。
- 已补充首次随机诊断、章节筛选排序、8 行渐进展开、结构化答案反馈、AI 默认收起与错因分析入口。

## 3. 是否重复

### 去重检查项

- 是否存在两组相同的常见问题。
- 快速开始、部署和开发章节是否反复给出相同命令。
- AI、知识库和账号能力是否在多个章节重复解释。
- 详细 Nginx、Docker 和 API 内容是否占据主 README。

### 去重审计结果

- 两组常见问题合并为一组。
- 主 README 只保留模式说明和文档入口。
- 详细部署配置集中到 `DEPLOYMENT.md`。
- 完整后端接口集中到 `BACKEND_API.md`。
- AI 和知识库章节分别说明用户行为，不再重复服务端部署细节。
- 学习仪表盘和间隔复习合并在一个章节中，算法契约只在 `BACKEND_API.md` 补充持久化要求，避免三处重复维护。
- README 负责项目介绍、启动、模式边界、开发与部署；`USAGE.md` 负责完整桌面端操作；应用内“使用说明”只保留当前页面需要的关键提示。

## 后续维护规则

功能变更后按以下顺序复查：

1. 修改代码和测试。
2. 更新 README 中面向普通用户的行为说明。
3. 同步 `USAGE.md` 与应用内“使用说明”中的用户操作。
4. 更新 `BACKEND_API.md` 或 `DEPLOYMENT.md` 中的实现细节。
5. 搜索已删除 UI 文案、配置项和快捷键，避免旧说明残留。
6. 执行 `npm test` 和 Markdown 本地链接检查。
